## Decisions (owner's words, 2026-10-09)

- Origin, from the orch plan: the memory skill gets its own repo, "that will work with Tartib
  in a way that anyone can attach any MCP for notes".
- Scope: a wider memory, not lessons only (owner chose "b"). Holds lessons, preferences and
  gotchas (today's `ai-agents` space), plus a user profile and references. Project facts stay
  in KIS; project status stays with orch and session-close; people are left out for now.
- "I don't want to depend on claude or codex or command code memory." Lore never reads or
  writes a host's built-in memory (except the one-time seed below).
- "it should work without host like tartib if no one adds then it should work." With no notes
  backend configured, lore runs fully on its own files.
- Built-in store: Markdown files in `~/.agents/memory/`, one file per note (chosen "a").
- Backends: one mapping file per backend under `backends/`, naming the tool for each operation
  (chosen "a"). Ships `files` and `tartib`; another MCP is added by writing one more file.
- Backend configured but unavailable: "if user added tartib or any mcp but it's not available
  then ask user to add back or give option to add mcp or connect mcp then fall back to files
  then update mcp when available to switch to files based." Confirmed reading: offer three
  choices (reconnect; files for now with writes queued and replayed when the backend returns;
  switch to files for good). No Fold during fallback. Snapshot refreshed at every load for
  the notes read, and in full at every retro.
- The owner's own setup: stay on Tartib, space `ai-agents`; add profile and references notes
  there, seeded once from Claude memory, CLAUDE.md and KIS Knowledge, reviewed before writing.
- Host memory: one redirect line in each global instruction file (chosen "a"). Turning host
  memory off is a later, separate step.
- Name: "ok let's do lore" (after `soul` was considered and set aside: it reads as an agent
  persona, and `SOUL.md` already means that in other agent tooling).

## Design

Operations every backend maps (in `backends/<name>.md`, with quirks and one read-only
reachability call):

| Operation | files | tartib |
|---|---|---|
| reachable? | store folder exists | `list_spaces` names the configured space |
| find a note | list the folder | `search` in the space |
| read a note with thoughts | read the file | `get_item` |
| add a thought | append a dated line under `## Thoughts` | `add_thought` |
| change a few words | exact-match edit, must match once | `find_replace` with `expected=1` and `updated_at` |
| rewrite a note (Fold) | write the file | `edit_item` with `updated_at` |
| delete a thought | remove its line | `delete_thought` |
| create a note | new file | `add_note` in the configured space |

Lore never creates a Tartib space; it only uses the configured one.

Store layout, the same whether it is the store (files backend) or the snapshot (any MCP
backend), so switching to files for good is a full snapshot plus a config change:

```text
~/.agents/memory/
  config            backend: files | tartib | <name>; per-backend settings (space)
  start-here.md     index: each note, when to read it
  preferences.md
  core-rules.md
  profile.md
  references.md
  coordinating.md
  gotchas/<stack>.md
  pending.md        queued writes made during fallback (MCP backends only)
```

Commands: `/lore:load`, `/lore:retro`, `/lore:fold`, `/lore:backend` (show config, check
reachability, reconnect, replay the queue, switch backend). Other hosts name the step.

The files-side mechanics (set up an empty store with starter notes, write the snapshot,
append to and list the queue, mark entries replayed) are scripts with tests, so every guard
can be mutation-checked. Backend mappings stay prose; Tartib is proved by dated live probes.

## Scope

New repo `~/Repositores/side-projects/lore-skill`, shaped like orch-skill: `skills/lore/`
(SKILL.md, four commands, `backends/`, `scripts/`), `bootstrap.sh`, `tests/`, its own `kis/`.

## Out of scope

- Turning off Claude Code's, Codex's or Command Code's built-in memory (later step).
- People memory; project status; project facts.
- Shipping orch's sub-agent definitions (an orch-skill task if wanted).
- Pushing to GitHub unless the owner asks.

## Phases

1. **Files alone.** Repo, installer (`bootstrap.sh install|check|update`, commands link
   `~/.claude/commands/lore`), `backends/files.md`, store scripts, SKILL.md and load, retro,
   fold on files.
   Acceptance: in a temporary home with no backend, the first load creates the starter notes
   from an empty store; retro adds a dated thought and raises an existing rule's `(×N)`; fold
   merges thoughts into the text, reads it back, then deletes them. Install tests in a
   temporary home; every guard mutation-checked.
2. **Tartib and the switch.** `backends/tartib.md`; install lore on the owner's machine with
   config `tartib`, space `ai-agents`; update the seven pointer files to lore (orch and
   session-close bumped, reinstalled from orch-skill, `check` current); remove
   `~/.agents/skills/agent-lessons`, `~/.claude/skills/agent-lessons` and
   `~/.claude/commands/lessons` only after lore's `check` passes.
   Acceptance: dated live probe on `ai-agents` (load reads preferences and core rules; retro
   adds a thought and bumps a rule; the probe's test thought removed after); no hit for
   `agent-lessons` or `lessons:` in live files; orch and session-close still work with lore
   present and absent. Advisor review before marking done.
3. **Profile and references.** The two notes and their place in `start-here`; the seed:
   only memory entries of type `user` and `reference`, plus facts from CLAUDE.md and KIS
   Knowledge, shown to the owner line by line before writing.
   Acceptance: both notes exist in `ai-agents` holding only approved lines; load reads them.
4. **Fallback.** Reachability check per backend; the three-choice prompt; snapshot at load
   and full at retro; the queue and its replay at the next load, before reads; no Fold in
   fallback; `/lore:backend`.
   Acceptance: with Tartib hidden, the prompt appears; queued writes replay on return; a
   replay failing halfway leaves only the unreplayed entries; Fold refuses in fallback; switch
   to files leaves a complete store that loads with no backend. Advisor review before done.
5. **Redirect.** One line in `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and
   `~/.commandcode/AGENTS.md`: cross-project memory is lore; save user, preference and
   reference facts there, never in the host's built-in memory.
   Acceptance: each file read back and names lore; agent-lessons named nowhere.

## Risks

- Tartib's tool names or rules may change under the mapping.
- Reachability looks different per host (ToolSearch in Claude Code, other ways elsewhere).
- Claude memory may come from another machine: check paths before trusting a reference.
- A partial snapshot misses notes never read on this machine until the first full retro.
