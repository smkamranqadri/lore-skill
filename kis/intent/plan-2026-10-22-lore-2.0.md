# lore 2.0.0: Tell it once

Mission: lore learns how the user works (preferences, tech stack, hard-won lessons) and every
coding agent and model they use already knows it. Vision: any coding agent, frontier or local,
knows the user from the first message; the memory is plain files in the user's own git repo.

Why now (measured 2026-10-22): hub sync through a model costs 40k to 90k tokens a run and failed
its first soak (80 of 81 timer runs timed out); 53% of the agent-visible memory text (37k of 70k
characters) is sync metadata. Ideas come from evaluating understory (thecodacus/understory,
`7625aa4`): a librarian agent, dream consolidation gated by code, links and lint, a graph UI.
Its weaknesses shaped this plan: writes piled into one note ("enrich over create"), facts were
reworded and merged on ingest (about 159 in, 135 out), and only a dream split the blob.

Work mode: Phase. Branch `lore-2.0`, built on the 1.1.0 work: the owner commits 1.1.0 and tags it
`v1.1.0` (not released) before P1, so a rollback has a target. Each phase installs on the owner's
machine as `2.0.0-p1` to `2.0.0-p4`; one 2.0.0 release at the end. Until P5, 2.0 runs **beside**
1.x: the 1.x modules, the Tartib sync, soak 2 and the 1.x index delivered to hosts all keep
working, and the session-end hook feeds both stores. Nothing 1.x is removed before P5.

## Decisions (owner, 2026-10-22)

| Area | Decision |
|---|---|
| Scope | Coding agents only (Claude Code, Codex, Command Code, agy). |
| Store | Fresh, empty git repo at `~/.agents/lore/`. Nothing migrates automatically; the 1.x store `~/.agents/memory/` keeps working until the switch, then is archived (not deleted). |
| Hub | Optional private GitHub: offered at install (created with `gh repo create --private` after asking), attachable later with `lore hub set <url>`, which does one test push and refuses a repository `gh` reports as public. Before every push: fetch and rebase; rule files merge by line union, sidecar fields merge by rule (below), `INDEX.md` is regenerated, never merged, and a `layout.json` conflict takes the hub's version and re-queues the local proposal. A failed push retries on the next run and is reported when it keeps failing. No hub: local git only, fully working. |
| Sidecar merge | Per field, so no machine's data is lost: `count` adds both sides' increments from the base; `dates` and `sessions` are unions; `created` is the earliest; `explicit` stays true once either side sets it; `reads` and `last_read` are a union of machines with the maximum per machine; every other field takes the newer by `updated`, compared as UTC instants (owner, 2026-10-23, on review decision 5). |
| Session-end lock | The 2.0 step has its own lock (`.git/lore/run.lock`), separate from 1.1.0's sync lock, so a slow 1.x sync and the 2.0 commit and push never wait on each other; it shares 1.1.0's log, timeout and backoff values (owner, 2026-10-23, on review decision 4). |
| Git, headless | Every git call runs with `GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND='ssh -o BatchMode=yes'`, `-c commit.gpgsign=false -c core.hooksPath=`, a local identity set at init, and the 1.1.0 timeout. |
| Tartib | Retired as lore's hub in P5; its `agent-memory` space is left as an archive. Hub code, `commands/sync.md` and the agent-driven sync are removed in P5, not before. |
| Rule files | Plain `- rule` lines only. Metadata (counts, dates, confidence, decay, reads, source sessions, the topic's `read_when`) lives in one sidecar per topic file, `.lore/meta/<path>.json`, committed, matched on rule text, never read by agents. Read counts go to the hub, kept per machine (`reads: {machine: n}`, `last_read: {machine: date}`) so a merge is a union of machines with the maximum per machine and never conflicts; a session's read counts ride in that session-end's single commit. First-added date, wording history and source session come from git. |
| Layout | Default top level in `.lore/layout.json`, not code: `profile.md`, `how-i-work/`, `preferences/`, `safety/`, `stack/`, `gotchas/`. The Loremaster picks topic files inside. A new, renamed or merged top-level folder is proposed and waits in the Inbox for the owner. |
| Index | Built by code from `.lore/layout.json`, the core list and each topic sidecar's `read_when` field: core rules (budget about 1,500 tokens) plus one read-when line per topic file. The Loremaster only writes `read_when`, through a `describe` operation (as `cmd_describe` does today). Delivery to the four hosts is unchanged; the 2.0 index replaces the 1.x one only in P5. |
| Core | Starts empty. Filed as core when stated outright and true for every task; otherwise a topic file. Canon proposes promotions and demotions from explicitness and the owner's decision, with file read counts only as a tiebreak (reads are per file, not per rule); each core change is its own commit. The filing session sets the first core with the owner. |
| Learning | Session-end harvest: a cheap model extracts candidates; promotion after two days or when stated outright. Changes from 1.x: the extractor no longer picks a category (the Loremaster does), the daily review is replaced by Canon, and the 25-rule cap per file is replaced by Canon's oversized gate. Command Code's `taste.md` stays an input. |
| Writing | Agents run `lore remember "<text>" [--explicit]` in the shell; no category. The queue is filed once per session end, with the harvest. No queue items and no new candidates means no Loremaster call. |
| Command | `setup` writes a `~/.local/bin/lore` shim (removed by uninstall) so every host's global file and every doc say `lore …`. |
| Loremaster | The librarian. Files, words, links, supersedes and answers chat. Returns JSON operations (add, describe, link, move, supersede, retire, flag-contradiction, propose-layout); code validates every operation before any write and applies them, like today's `apply_review_ops`. No MCP server. Its prompt holds the index (all read-when lines) plus the three topic files with the highest word overlap with the item, under a size cap. |
| Inbox | What waits for the owner (layout proposals, retirements, core swaps, unmatched hand edits, the filing session) is acted on with `lore inbox list\|accept\|reject <id>` from P2; the UI calls the same functions. |
| Canon | The dream. Checked at every session end after the harvest; runs only when a code gate fires, at most once a day (contradiction or core overflow skips the wait). The contradiction gate fires from a `flag-contradiction` the Loremaster recorded at filing time (code cannot see a contradiction). One commit per change. Rewording is applied and revertable; meaning is checked against the original quote, never only the previous wording. Retiring a rule waits in the Inbox. |
| Models | Through the host CLIs already installed (no API keys). Extract cheap, Loremaster mid, Canon strong. Per role in config (`loremaster:`, `canon:`), editable in the UI. Every command uses an absolute binary (soak 1: the mise wrapper hangs without a TTY). Every call is stateless and ephemeral, as today's adapters are. |
| Read tracking | From the transcripts the harvester already locates, with one new per-host reader for tool calls (Claude `tool_use`, Codex `function_call`, agy and Command Code to be verified); per file. The stale gate stays off while any installed host reports no read data, and its report names that host. |
| Host memories | Applied in P5. Each switch is its own yes/no in `setup`: Claude Code `autoMemoryEnabled: false` (best effort: reported when the installed binary no longer has the key), Codex `[features] memories = false` (edited by line with a marker comment, refused when `tomllib` cannot read the result back). lore records each key's prior value (absent or its value) and uninstall restores that key only. Every host's global file routes remember, always and never to lore. |
| UI | `lore ui` on demand: stdlib server on `127.0.0.1`, first free port from 3870. The token is sent in a request header on every call (never a cookie) and dies with the process; the server checks the `Host` header is `127.0.0.1` or `localhost` and sends no CORS headers. React + Vite + Tailwind source in repo-root `ui/` (contributors only, node pinned in `engines`, lockfile committed); built bundle in `skills/lore/ui/dist/`; CI rebuilds and compares sorted file hashes. d3-force graph. 2.0.0 ships Memory, Graph, Inbox and Changes (P4a); Chat and Settings follow 2.0.0 (P4b). |
| Dependencies | Runtime stays Python stdlib, git and the agent CLIs. README badge becomes "no runtime dependencies". |
| Quality | `lore eval loremaster` and `lore eval canon` on about 60 fictional rules, run by hand against the real configured model before the filing session, against the bars below. The fixture carries, per rule, the expected `folder` and `related: [ids]`, and is frozen (committed) before the Loremaster is built. |
| Tests | Never a real model or network: fakes through `LORE_EXTRACT_CMD`, `LORE_REVIEW_CMD`, `LORE_LOREMASTER_CMD`, `LORE_CANON_CMD`; a local bare repo as the hub; `GIT_CONFIG_GLOBAL=/dev/null`. AGENTS.md is updated in P1 to name them. |

## Phases

**P1 Store and hub, beside 1.x.** `lore_store` (git repo at `~/.agents/lore`, layout, sidecars,
text matching, adopt hand edits), index build by code, headless git, `lore hub set|status` with
the test push and the public-repo refusal, fetch-rebase-push with the merge policy, auto-push
with retry, a commit-time secret scan that refuses a commit (reusing `SECRET_RE`), read tracking
(the per-host tool-call readers; one real transcript per host checked; a host that cannot be
parsed reports no read data), installer prompts for the hub, the `lore` shim, 1.1.0's trigger,
gate, lock, log and backoff reused for commit and push. The hook feeds both stores; 1.x keeps
its index, its Tartib sync and soak 2.

**P2 Loremaster.** `lore remember`, the queue, the operations schema and its validator, the
filing run at session end (no call when nothing is queued), the prompt's file selection and size
cap, `lore inbox`, per-role host commands from config, `lore check` running each role headless.

**P3 Canon.** Lint: orphans and broken links (generated index files excluded as link sources),
duplicates (word overlap; identical text in two files counts), oversized (default 25 rules or
4,000 characters), thin (fewer than 2 rules for a week), stale (unread 60 days), contradiction,
core budget. Gates, the once-a-day limit, Canon runs, a hub split that keeps the old path,
`retired/` for retired rules, `lore canon-log` from git. A quiet store makes no model call.

**P4a UI for 2.0.0.** Memory, Graph, Inbox and Changes: the token and Host checks, revert from
Changes, Inbox actions through `lore inbox`'s functions, the d3-force graph with heat and orphans.
Playwright tests in `ui/`; the dist hash check in CI.

**P5 Eval and switch.** The eval runs; a rollback to `v1.1.0` proven once in a temp home (install
`--ref v1.1.0`, settings restored, store un-archived, 1.x index delivered, hooks and timer back)
under a documented command list; the filing session (each 1.x rule plus the Claude memory entries
the taxonomy pass marked to file; project facts go to their KIS; the owner confirms core);
prompts for the owner's stack defaults; host memory switches, each its own yes/no; 2.0 index
delivered to hosts; Tartib hub code, `commands/sync.md` and the agent sync removed; old store
archived; docs, README, CHANGELOG, version 2.0.0; release (the owner commits and tags).

**P4b after 2.0.0.** Chat (stateless: each turn resends the thread so far) and Settings (writes
config through the same validator as `lore config`).

## Acceptance

Every phase: `tests/run.sh` green; every new guard mutation-checked (break it, watch its test
fail, restore byte-identical); `bootstrap.sh update --source .` and `check` pass on the owner's
machine; soak 2's `sync-log` shows 1.x runs after the install (until P5); an independent review by
a different CLI and model than the builder.

- P1: fresh install with and without a hub; a commit pushes (checked on GitHub from outside); an
  offline push retries; `hub set` refuses a repo a fake `gh` reports as public; a seeded fake
  secret is refused; agent-visible files carry no metadata; two temp stores sharing one bare repo
  both commit (including read counts) and end equal; git under no TTY with a hostile global config
  (signing on, a hooks path, no identity) still commits and pushes or fails within the timeout;
  reads counted from a real transcript per host that has one.
- P2: a `lore remember` from a real session is filed at session end, committed and pushed; a
  session with nothing queued makes no Loremaster call; an invalid operation (unknown folder, rule
  text altered outside a reword op, path escape) is rejected by code; a layout proposal is
  accepted from the shell with `lore inbox accept` and lands as its own commit; the prompt size
  cap holds (test).
- P3: each gate fires on a fixture and its fix lands as its own commit; a quiet store makes no
  model call; an orphan is not hidden by an index file; the stale gate stays off when a host has
  no read data.
- P4a: Playwright green in CI; the dist check fails on a stale bundle; a request without the token
  header, or with a foreign `Host`, is refused (test); screenshots of the four screens looked at.
- P5: rollback to `v1.1.0` proven in a temp home; each host memory switch set and restored key by
  key by uninstall (test with a settings file holding other keys); the Codex edit survives a file
  that already has a `[features]` table.
- P5 eval bars (fixed now, reported as measured fractions with their denominators, never moved):
  at least 90% of fixture rules in the expected top-level folder; no topic file over the
  oversized limit after filing; at least 80% of the expected related pairs linked; meaning kept
  for 15 of 15 spot-checked rules, judged yes or no by the owner against the original wording;
  every Canon gate's fix present. Each run logs model, effort, tokens and time.

## Out of scope

Chat agents and remote MCP; Tartib as a hub; macOS (no Mac); several memories or profiles; path
by path trace replay; mobile layout; hot memory and query cache; knowledge-gap lint (filed in
Tartib's backlog instead).

## Risks

- A secret reaching the hub: the commit-time scan, plus lore's existing never-store-secrets rule.
- Meaning drift under repeated rewording: Canon compares with the original quote; the eval checks.
- Headless CLI hangs: absolute binaries per role; `lore check` runs each.
- Transcript formats differ per host: read tracking degrades per host, visibly.
- UI size: split already (P4a in 2.0.0, P4b after).
- A web page in the same browser posting to the localhost UI: header token, Host check, no CORS.
- Git prompts or a signing setup hanging a session-end commit: the headless git settings.
- Two machines diverging: fetch-rebase before push, the merge policy, the shared-bare-repo test.
- Quota: Canon, the Loremaster and the eval spend the owner's subscription; logs record tokens.
- Turning off Claude's auto memory stops project memories there; KIS holds project facts, and
  the filing session lists the Claude entries that belong in a project's KIS.
