# Plan: lore 1.0.0, one memory every host learns from (approved 2026-10-16)

Interviewed and approved by the owner on 2026-10-16 in an orch-skill session, after a landscape
study (doc: "Agent Stack Landscape Report"). Work mode: Phase. One phase is proved and checked
before the next begins. Status and proof live in State.

## Why

Agents repeat mistakes another host already learned ("claude knows but codex does not"), and
the owner's workflow and tech preferences must reach every host so no time is lost on work
they dislike. Today's lore costs 5-17k tokens at start, needs manual load, retro and fold, and
reaches hosts only by hand-copied global files. Command Code's taste showed that automatic
capture works (149 entries learned across 7 projects), but it is per project, Command Code only,
and mixes project facts and contradictions into general rules.

## Decisions (owner, 2026-10-16)

- Name stays `lore`; the concept is memory. KIS and orch changes are planned after lore is done.
- Hosts: Claude Code, Codex, Command Code (cmd) and agy, all on the same layer. New hosts are
  added later as one adapter each.
- Hub: Tartib, new space `agent-memory` (name approved). The `ai-agents` space stays as an
  untouched archive. Files at `~/.agents/memory/` are the local cache every host reads.
- Auth: no token. Hooks and the worker touch local files only; an agent session with the Tartib
  MCP pushes and pulls (`/lore:sync`). Machines catch up when an agent session runs on each.
- Capture: fully automatic. A rule is promoted when seen in 2+ sessions on different days, or
  when stated explicitly ("remember:", "always", "never"). Each promotion shows once as `New:`
  in the index; "drop that" deletes and blocklists it.
- Budget: an index of about 1.5k tokens loaded at start on every host; categories on demand.
- Seed: taste files plus `ai-agents`, merged and imported automatically; contradictions resolved
  by recency and confidence and listed in an import report for later veto.
- Project facts are never stored; lore says the fact belongs in that project's KIS.
- Extractor: cheapest available CLI (Codex gpt-6-astra low, then Claude haiku low, then cmd, then agy),
  configurable, with the extractor's own hooks disabled.
- Taste: Command Code's taste learning stays on; `/lore:learn-taste` harvests its files,
  manually or from cron.

## Phases

1. **Store and format.** `~/.agents/memory/`: `INDEX.md` (hard rules and top preferences inline,
   one "read when" line per category, capped at 1.5k tokens), `<category>.md` (entries
   `- rule. Confidence: x <!-- seen:date n:N src:"quote" -->`), `candidates.md`, `blocklist`,
   `queue/`, `config`. Rewrite `lore-store.sh`: merge by normalised text, promote, decay
   (candidates gone after 28 days unseen; confirmed lose 0.05 per unseen month, removed below
   0.40), cap 25 per category, regenerate the index.
2. **Delivery.** `skills/lore/hosts/<host>` adapters: global-file path, import or marked block
   (`<!-- lore:index -->`), hook install, payload field names, transcript reader.
3. **Capture.** Each host's end or Stop hook only queues (host, id, transcript) and exits fast.
   A detached worker (`setsid`, `LORE_HARVEST=1` guard) reads each transcript from its last
   offset, regex-scans user messages (most sessions stop here, no model call), extracts with
   the extractor chain, drops project facts, merges candidates. A SessionStart sweep catches
   missed sessions.
3b. **Daily review** (added by the owner 2026-10-16, after phase 3). `lore.py review` runs at
   most once a day: the first harvest of the day triggers it, or cron or `--force`. A strong model
   (Claude Opus, then Codex at high effort; configurable) reads the candidates and the rules that
   changed since the last review. It returns operations: merge near-duplicates, rewrite into a
   scoped rule (to resolve a contradiction), reject junk or project facts, veto a fresh
   promotion. lore applies only operations on ids that exist, and logs every decision with its
   reason. Industry basis: Codex memories (separate extract and consolidation models), mem0
   (extract, then update against existing memories).
4. **Sync.** `/lore:sync` (`commands/sync.md`) has the agent move `lore/<file>` notes between the
   Tartib space and a folder; `lore.py merge`, `export`, `sync-status` and `sync-done` do the
   exact part. Removals travel as tombstones; entries keep their recent distinct dates; the merge
   is order independent and idempotent. The index asks for a sync only when local files changed
   since the last push or the last sync is over a day old. Create the space; configure the Tartib
   MCP on all four hosts (phase 7).
5. **Seed.** Merge `.orch/lore-v1/seed/seed-taste.md` and `seed-tartib.md`; import automatically;
   write the import report (contradictions resolved, stale and project facts dropped, counts).
6. **`/lore:learn-taste`.** Read `.commandcode/taste/**` directly (`cmd learn-taste` needs a
   keypress); cron optional.
7. **Install.** lore 1.0.0 on this Linux machine for four hosts (agy reads global skills only from
   `~/.gemini/config/skills/`, so it needs a link there); remove `load`, `fold`, `backend`
   and the backend machinery; README and tests. The Mac waits for a separate approval.

## Out of scope

KIS and orch changes, the `kis:start` front door, scoped Tartib tokens, the Mac install,
deleting `ai-agents`, exporting to taste.md.

## Acceptance checks

- The index block in each global file is at most 1.5k tokens, measured.
- A fresh session on each host cites a rule from the index.
- A scripted correction transcript yields a candidate; a second fake-dated session promotes it;
  "drop that" deletes and blocklists it.
- A session with no regex hit makes no model call; the guard stops recursive hooks.
- Offline, the index loads from cache and the queue survives until the next sync.
- Seed counts match the import report; no project fact or stale rule is imported.
- `tests/run.sh` passes and every guard is mutation-checked.

## Risks

agy hooks may not fire; Codex hooks need one-time trust; cmd transcript format is unverified;
sync is lazy across machines; automatic promotion can learn a wrong rule (veto, decay and the
import report contain it). The seed holds the owner's preferences: it stays in the ignored
`.orch/` folder and never enters this public repo.
